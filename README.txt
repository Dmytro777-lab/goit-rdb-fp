ПОРЯДОК ВИКОНАННЯ
1. Відкрийте 01_import.sql у підключенні до MySQL та виконайте весь файл.
   У результаті imported_rows має дорівнювати 10521.
2. Відкрийте queries.sql та виконуйте блоки послідовно.
3. Збережіть скриншоти SQL-запитів разом із результатами.

Скрипти призначені для першого запуску. Вони не видаляють наявні бази.
Не запускайте блоки CREATE та INSERT повторно: це може дати помилки
існування об'єктів або повторно додати початкові рядки.
Якщо виникла помилка, зупиніться та перевірте Output перед продовженням.

НОРМАЛІЗАЦІЯ ДО 3НФ
infectious_cases_raw — допоміжна копія CSV для перевірки імпорту;
вона не є частиною нормалізованої моделі.
Нормалізована модель має дві таблиці:

entities:
  entity_id — первинний ключ;
  Entity — унікальна назва країни, території або групи;
  Code — код, якщо він присутній у CSV.

infectious_cases:
  entity_id + Year — складений первинний ключ;
  entity_id — зовнішній ключ до entities;
  інші колонки — показники захворювань для сутності за конкретний рік.

У CSV кожній назві Entity відповідає один Code; назва може бути ключем.
Code не використано як ключ: у різних регіонів він може бути порожнім.
Властивості сутності винесено з річних спостережень до entities.
У entities неключовий атрибут Code залежить від ключа сутності.
У infectious_cases показники залежать від повного ключа (entity_id, Year),
а назви та коди більше не повторюються у кожному річному спостереженні.
Виходячи з цих залежностей, модель відповідає третій нормальній формі.

ПОЯСНЕННЯ ЗАПИТІВ
NULLIF(TRIM(значення), '') перетворює пропуск на NULL, а не на 0.
CAST(... AS DECIMAL(24,12)) зберігає дробові значення вихідного CSV.
Оператор <=> дозволяє приєднати також сутності з відсутнім Code.

У блоці 3 WHERE Number_rabies IS NOT NULL відкидає пропуски.
GROUP BY формує групу для кожної сутності; AVG, MIN, MAX та SUM
обчислюють статистику. ORDER BY avg_rabies DESC і LIMIT 10
залишають десять груп із найбільшим середнім значенням.
Країни та агреговані регіони збережено як у джерелі; їх не слід
додавати разом для оцінки загальної кількості випадків у світі.

У блоці 4 MAKEDATE(Year,1) створює 1 січня відповідного року.
CURDATE() повертає поточну дату сервера.
TIMESTAMPDIFF(YEAR, початкова_дата, поточна_дата) рахує повні роки.

У блоці 5 years_since приймає рік і повертає ту саму різницю.
NOT DETERMINISTIC вказує, що результат може змінюватися з датою.
NO SQL означає, що функція не читає і не змінює таблиці.
Одне RETURN не потребує BEGIN/END або зміни DELIMITER.
